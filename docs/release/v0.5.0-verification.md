## 后端与安全实现证据

- ACME 账户按 staging/production 隔离，支持创建、导入、当前 Terms 明确同意和停用；生产只使用固定 Let's Encrypt directory，测试 directory 只能通过内部构造依赖注入。
- Cloudflare 客户端固定生产 origin，禁用环境代理、redirect、Cookie jar、压缩和无限响应；Token 仅通过 `Authorization: Bearer` 发送。创建凭据前验证 Token active 与可读 Zone，API 之后只返回名称、SHA-256 指纹前缀和验证时间。
- Cloudflare Token 使用 AES-256-GCM、credential ID/schema AAD 和独立 `0600` master key 加密；账户密钥、证书私钥和证书链使用固定 root、owner-only 目录、原子创建和 `0600` 文件。
- DNS-01 使用最长 Zone 后缀、任务持久化的 exact `zone_id + record_id`、Cloudflare 回读和权威 DNS 精确值观察；清理不按名称删除用户已有同名 TXT。通配符仅允许最左单标签并强制 DNS-01。
- HTTP-01 只生成 exact `/.well-known/acme-challenge/<token>` location；临时 include 的发布与清理都复用配置工作区、完整 `nginx -t`、备份、原子发布、reload 和运行确认。
- 签发结果在提交前验证 SAN 精确集合、私钥匹配、有效期、serverAuth、非 CA 与 PEM 边界；版本目录不可变。部署失败或结果不确定时不把新版本写成活动元数据，旧配置和旧证书继续可用。
- server 绑定由 source-derived ref 和生产摘要定位，先返回逐文件 diff；执行时重新解析并复核同一 diff。绑定、续期、解绑和删除均复用既有安全发布链路或执行最新生产引用检查。
- durable task 支持有界并发、SSE 重连、取消、超时、阶段历史、启动对账和 `needs_attention`。自动续期使用持久化到期时间、固定 ±12h 抖动、1h–24h 指数退避和最多四个并发网络任务。
- 审计期间补充了待执行任务取消回归：pending task 现在持有自己的 cancel function，并在取得执行槽和转入 active 前再次检查取消状态，不会在取消后启动网络流程。

## ACME、持久化与真实 Nginx

执行本地 ACME 专项：

```sh
go test ./internal/certificate -run TestXCryptoACMEClientCompletesLocalIssuanceRenewalAndDeactivation -count=1 -v
```

结果：PASS，HTTP-01 与 DNS-01 均完成账户、order、authorization、finalize、renewal 和 deactivation。测试服务和 CA/账户/证书密钥均在测试期动态生成，没有访问 Let's Encrypt production/staging 配额，也没有固定测试私钥进入仓库。

执行持久化与契约专项：

```sh
go test ./internal/store -run TestCertificateRepositoryPersistsRenewalInventoryAcrossReopen -count=1 -v
go test ./internal/httpapi -run 'Test(OpenAPIContract|BusinessAPIRouteContract)' -count=1 -v
```

结果：PASS。数据库关闭重开后，账户、证书版本、绑定和 due renewal 顺序仍可用；OpenAPI 与实际注册路由一致。

执行真实 Nginx：

```sh
NGINX_UIX_INTEGRATION=1 NGINX_BIN=/opt/homebrew/bin/nginx \
  go test ./internal/runtime ./tests/integration -count=1 -v
```

结果：PASS。

- production renderer 生成的 exact HTTP-01 location 只响应精确 token；near match 为 404，清理并 reload 后精确路径也恢复 404，master PID 不变。
- 两个动态 P-256 证书先经过生产证书校验，再由真实 HTTPS/SNI server 提供；第二个 SNI 返回正确证书和内容。
- 写入无效候选后 `nginx -t` 失败，未 reload；旧证书、旧响应和运行中 master 保持可用。
- 既有真实 Nginx release、restore、restart、Route Lab 和容器默认配置集成回归同时通过。
