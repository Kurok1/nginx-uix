## 最终最小修正的红绿证据

最终审查发现并修正三个 fail-closed 边界：

1. succeeded/rolled_back/needs_attention 或备份已验证后的终态，必须携带与 release ID、backup ID 和生产摘要完全绑定的完整备份证据。
2. 备份索引无法持久化时，release 与工作区进入 `needs_attention`，不能停留在 running 或报告成功。
3. 备份树冻结后发生容量/同步类故障时，先在固定备份根内不跟随 symlink 地恢复目录可写性，再删除并同步父目录，不留下伪完整备份。

修正前，新增测试实际得到两类失败：缺失备份证据被错误接受为 `succeeded`；备份索引失败后 release 留在 `running`；冻结后测试因缺少注入点无法编译。修正后只执行以下受影响测试：

```sh
go test ./internal/config \
  -run 'TestReleaseServiceFailsClosedWhenTerminalBackupEvidenceCannotBeIndexed|TestReleaseServiceCreatesBoundCheckAndPublishesWorkspace|TestReleaseServiceReconcilesInterruptedAgentTransaction' \
  -count=1

go test ./internal/runtime \
  -run 'TestAgentClientRejectsTerminalReleaseEvidenceNotBoundToRequest|TestAgentClientRoundTripsCandidateAndReleaseTypedOperations|TestCreateBackupThawsAndCleansIncompleteDirectoryAfterTreeFreeze|TestCreateBackupWritesCompleteImmutableTreeAndDetectsTampering|TestReconcileReleaseArtifactsRemovesOnlySafeAbandonedState' \
  -count=1
```

结果：两个包均 PASS，共 8 个顶层定向场景及其子场景。依用户指令，最小修正后未重复全局 Go、race、前端、E2E 或真实 Nginx 套件。

## 关键失败路径证据

| 场景 | 证据结论 |
| --- | --- |
| 无效候选 | 只返回相对路径、行号、安全 code/summary；不写生产、不 reload |
| 检查后生产或草稿变化 | 写生产前拒绝，返回稳定冲突/过期错误 |
| 备份损坏或身份不匹配 | 完整重读清单和树后拒绝，不进入成功终态 |
| reload 失败 | 恢复备份、完整复验并确认健康；否则 `needs_attention` |
| HTTP 非 2xx / 健康超时 | 自动回滚，不把命令退出 0 当成功 |
| 生产并发修改 | 按阶段拒绝、回滚或保留未知内容并进入 `needs_attention` |
| 只读目录 / 磁盘满 | 不完整备份被清理，生产恢复且不报告成功 |
| journal 中断 / Agent 进程退出 | 启动恢复得到 failed、rolled_back、succeeded 或 `needs_attention` 的唯一持久终态 |
| SQLite/阶段/备份索引失败 | CAS 失败不越级；不确定结果阻断工作区 |
| SSE 断开与重连 | 任务不随浏览器取消；`Last-Event-ID` 有界，刷新从持久化资源恢复 |
