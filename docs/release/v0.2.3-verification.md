## 最终 restore 状态机修正的红绿证据

最终矩阵审查为 restore 增加了直接失败路径与崩溃点测试。修正前，新增测试实际得到两类错误：

1. journal 已处于 `rollback_applying` 且生产仍是目标摘要时，恢复逻辑错误地进入 `succeeded`。
2. 从 `rollback_validated` 或 `rollback_reload_requested` 恢复时，事件流追加了更早的 `rollback_files_restored`，后续读取报 `restore event sequence is invalid`。

最小修正将 rollback 已开始作为不可逆的恢复决策，并只执行、记录尚未持久化的后续阶段。修正后仅执行：

```sh
go test ./internal/runtime \
  -run '^(TestExecuteRestoreRollsBackToSafetyBackupWhenReloadFails|TestExecuteRestoreNeedsAttentionWhenRollbackReloadCannotBeConfirmed|TestRecoverRestoreResumesEveryRollbackStageWithoutRegression)$' \
  -count=1 -v

go test ./internal/runtime \
  -run '^TestRecoverRestoreClassifiesEveryForwardDurableStage$' \
  -count=1 -v

go vet ./internal/runtime
golangci-lint run ./internal/runtime
```

结果：PASS。覆盖 safety rollback 成功、rollback 无法确认进入 `needs_attention`、4 个 rollback 中断点，以及写入前、部分写入、写入完成、生产校验、reload 请求和 runtime 确认 6 个前向持久点；定向 lint 为 `0 issues`。依用户指令，没有在该最小修正后重复全局 Go、race、前端、E2E 或完整真实 Nginx 套件。

同一矩阵核对还只补充执行了现有 restart fail-closed 行为的定向测试：

```sh
go test ./internal/runtime \
  -run '^(TestExecuteRestartSupervisorTimeoutAndCancellationNeedAttention|TestExecuteRestartPortConflictAfterAcceptedRequestNeedsAttention)$' \
  -count=1 -v
```

结果：PASS。监督器请求超时/取消进入 `needs_attention`；请求已接受但新进程因端口冲突处于 stopped 时进入 `restart_runtime_unconfirmed`，均不误报成功。

## 关键失败路径证据

| 场景 | 证据结论 |
| --- | --- |
| 损坏/身份不匹配的恢复目标 | 在创建任务或写生产前拒绝，生产摘要与 runtime 不变，API 返回稳定 422 |
| restore 写入、校验、reload 或健康失败 | 使用已验证 safety backup；能确认则 `rolled_back`，否则 `needs_attention` |
| restore 任一持久点进程退出 | 从摘要、durable operation 和单调 journal 唯一恢复，重复读取不产生倒序事件 |
| restart 前配置无效 | supervisor 不调用，生产和 runtime 不被额外改变 |
| restart 超时、取消或端口冲突 | 已接受但结果不确定时进入 `needs_attention`，不以命令返回替代运行证据 |
| restart 命令已接受但新 runtime 不可确认 | 进入 `needs_attention`，不把命令退出 0 当成功 |
| retention 计划后保护事实变化 | 删除前 CAS 重检并 `skipped_protected` 或过期，不删除保护项 |
| retention 删除中断/正文不确定 | tombstone 对账为 complete、deleted 或 `needs_attention`，无幽灵成功 |
| open attention | 阻断普通工作区 create/edit 和新发布；只有成功 restore/restart/固定 verification 可关闭 |
| SQLite/Agent/UI 进程重开 | 非终态任务在绑定 UI 端口前对账，精确释放 lease 并保留审计证据 |
| SSE 断开与重连 | 浏览器断开不取消任务；`Last-Event-ID` 有界并从持久资源恢复 |
