## 测试先行与最小修复

实现中实际确认了以下失败，再完成最小修正：

1. 同一直接来源对不同用户名进行第 20 次失败登录时仍返回 `invalid_credentials`。新增持久 source bucket 后，20 次/5 分钟阻断 15 分钟；重启后仍阻断，独立来源不受影响，成功认证清除对应来源桶。
2. Agent Socket 所有权复核测试先因 `ownerMatches` 不存在而编译失败。新增平台元数据检查后，`chown` 即使静默未生效也会启动失败并安全清理本进程 Socket。
3. 证书页错误一致性测试证明页面会直接回显后端中文 message 和内部路径。修正后只按稳定 error code 输出同语言操作建议，并附安全 request ID。
4. 发布候选浏览器主旅程首跑在 1280px 等待不存在的 drawer trigger。失败 snapshot 证明该断点使用常驻三栏 review；测试改为操作真实可见 region 后通过，没有扩大超时或降低断言。

日志脱敏、灾备和兼容矩阵属于发布回归证据；新增测试直接锁定现有安全行为，未人为制造产品实现变化。

## 安全审计结果

### 认证、会话、CSRF 与日志

- 保留 Argon2id、missing-user dummy hash、通用凭据错误、digest-only Session、derived CSRF、8h idle/24h absolute、严格 Origin 和 `HttpOnly; SameSite=Strict` Cookie。
- 既有“规范化用户名 + direct peer IP”5 次/5 分钟限流之外，新增不可能与合法用户名冲突的 source bucket：同一 direct peer IP 跨用户名 20 次/5 分钟后阻断 15 分钟。状态复用 `login_throttles`，不新增 migration，也不信任 `X-Forwarded-For`。
- 请求日志回归显式提交 query secret、Authorization、Cookie 和 Body secret，日志只包含 method/path/status/request ID，不包含四类秘密。
- 全量 API/浏览器测试继续覆盖登录/登出及业务 mutation 的 Cookie、Origin、CSRF、`If-Match`、strict JSON、`no-store` 和安全错误 envelope。

### Unix Socket 与 Agent

- Socket 设置后重新 `lstat`，验证 same-file、Socket 类型、UID 0、GID 10002 和 mode 0660；任一步不一致均 fail closed。
- peer UID 10001 在 HTTP 解析前校验；其他 UID 或凭据读取失败会关闭连接。
- 既有白名单测试覆盖固定 GET、config、release/recovery、Route Lab 和证书类型化操作；未知 path/method、query、重复/未知字段、绝对路径字段、超限 Body 和错误 request ID 在调用运行时前被拒绝。
- Agent 仍不接受 `/exec`、`/bin/sh`、任意命令、可执行路径、生产根、PID、signal 或透传 URL。

## Nginx 兼容矩阵

- 新增 5 个 compatibility fixture，覆盖多文件 include、map、IPv4/IPv6/Unix upstream、backup/down/max_fails/fail_timeout、exact/prefix/`^~`/regex/named location、wildcard/regex server name、proxy、try_files/error_page，以及只做 lossless 验证的未知第三方模块语法。
- `TestCompatibilityFixturesRoundTripLosslessly` 对所有 fixture 做 byte-for-byte parse/render；端口占位先替换成实际配置值。
- `TestCompatibilityMatrixWithRealIsolatedNginx` 使用本机 Nginx、随机回环端口、临时 prefix/PID/log 执行 `-t/-T`；未知模块 fixture 明确不送入真实 Nginx。
- 既有真实回归同时通过 repeated/nested include、invalid config 无残留 master、取消清理、exact/prefix/regex/nested/rewrite/try_files/error_page 路由矩阵、HTTPS SNI、HTTP-01、release/restore/restart 和 production master/listener/digest 隔离。

## 浏览器、任务状态与错误文案

新增 `web/e2e/release_candidate.spec.ts`，在同一 browser context 中依次完成：

1. 键盘登录并建立 HttpOnly Cookie；
2. 完整 diff review、candidate check、具名确认发布，显示 release/backup 与健康终态；
3. Route Lab 静态分析和 GET 隔离运行，明确 production Nginx 未 reload；
4. production wildcard Cloudflare DNS-01 plan、staging/risk 精确确认和持久证书 task 成功历史；
5. 带当前 Origin/CSRF 的 logout，并证明 protected deep link 重新要求认证。

每段 mock 切换前解除旧 route，同一 Cookie/Session 保持；所有 mutation 继续校验 Cookie、Origin、CSRF 和领域并发边界。该 mock 旅程只证明浏览器交互/HTTP 契约，真实 Nginx 与本地 ACME 由原生测试证明。

Release/restore、Route Lab 和 certificate 的 queued/running/cancelling/succeeded/failed/rolled_back/cancelled/timed_out/needs_attention 状态继续由 Go、TypeScript parser、store CAS、SSE 和可见终态组件测试覆盖。证书操作面不再展示未知后端 message；`needs_attention`、rollback 和普通失败保持不同文字与语义角色。
