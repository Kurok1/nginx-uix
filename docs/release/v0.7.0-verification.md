# Nginx UIX v0.7.0 验收证据

## 当前结论与边界

- v0.7.0 Docker 一体化统一验证版已完成。该版本没有新增产品模块、REST 资源、Agent 操作或数据库 migration；工作集中在最终镜像、容器生命周期、持久化升级、故障恢复、安全边界、浏览器隔离、供应链和多架构验证。
- 被测源码位于 `main` 的当前工作树。本次没有推送、创建 tag、创建 PR 或发布远端镜像；`nginx-uix:0.7.0-acceptance` 只是本机验收候选。
- Docker daemon 为原生 `linux/arm64`。arm64 完整运行验收通过；amd64 OCI 构建、配置、文件系统描述符、标签、healthcheck 和 SBOM 静态验收通过，但没有真实 amd64 runner，因此未把模拟运行写成原生通过。
- 按最终确认的验收范围，PID 1 覆盖真实 `SIGTERM`、有界优雅停止、零状态退出和同卷重建；UI、Agent 与 Nginx 覆盖独立崩溃/恢复。未另行增加 PID 1 强制 `SIGKILL` 场景。

## 测试先行发现与修复

Docker 验收首先暴露并通过失败测试锁定了三项既有闭环缺陷：

1. 新发布文件固定写成 `0640`，没有遵循 draft manifest mode。新增失败测试后，发布改为保留 manifest 的权限位。
2. ACME finalize 前没有显式等待 order 进入 `ready`。新增协议测试后，客户端先等待并校验 `ready`，再 finalize。
3. 证书绑定持久化了发布前 server fingerprint，续期时会把绑定后的 `listen 443 ssl` 误判为并发修改。新增失败测试后，发布前引用继续用于事务校验，发布后引用单独用于持久化与续期。

对应 Go 单元、证书集成和全仓质量门禁均在修复后通过；没有通过降低断言、增加跳过或吞掉错误完成验收。

- linux/amd64 缺少原生 runner；OCI/SBOM/静态内容已通过，原生 runtime 与 workspace 仍由 v1.0 发布环境补齐。
