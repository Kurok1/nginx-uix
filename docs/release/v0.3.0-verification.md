# Nginx UIX v0.3.0 验收证据

## 结论与边界

- v0.3.0 结构化 upstream 与 location 版已完成：lossless tokenizer/AST、跨文件语义投影、upstream 与 server CRUD、六类 location、嵌套规则、`proxy_pass`、静态诊断、确定性 preview、可恢复批量草稿事务、版本化 REST API 和双管理页面均有可复现证据。
- 结构化模型不是配置真源。browse 与 preview 只读取一次已验证的 workspace draft snapshot，apply 只调用既有 workspace `ReplaceFiles` 批量事务；没有新增生产配置写入口，也不能绕过 v0.2.2/v0.2.3 的 check、backup、publish、reload 和 recovery 链路。
- 被测分支为 `feat/v0.3-structured-config`，独立 worktree 基于提交 `c82b444`。本文记录的是未提交实现；本次没有提交、推送、打 tag、合并到 `main` 或发布镜像。
- Docker 构建、容器运行、卷、升级、容器故障和 multiarch **均未运行**，统一属于 v0.7.0。完整 Playwright 套件中的既有 Docker 工作区场景按环境条件跳过，没有被标记为通过。
- v0.4.0 的真实路径命中实验、沙箱请求和 Route ID 不在本版本范围内。动态或无法安全分类的语法保持 raw-only，并提供原始文本编辑回退。

核心证据包括：

- tokenizer 保留全部原始 byte、1-based rune line/column 和 byte source span；parser 支持引号、转义、变量、正则、CRLF、空块、深层块及稳定错误码。
- no-op render 与输入逐字节相同；插入、更新和删除只应用无重叠 span，目标范围外保持不变，结果可再次 parse。golden 与 fuzz 覆盖 lossless 不变量和不 panic 边界。
- project builder 依据 workspace 已验证 include dependency 建立跨文件 `http`、`server`、`upstream`、`location` 上下文；missing、external、cycle、ambiguous、syntax error 和上限均 fail closed。
- upstream 支持 create/rename/delete、server create/update/delete、IPv4/IPv6/domain/Unix Socket、port、`weight`、`backup`、`down`、`max_fails`、`fail_timeout`，并保留未知参数和未知指令。
- upstream rename 在一个批量事务中更新 block header 与跨文件 direct `proxy_pass` 引用；被引用删除、动态引用、不完整引用分析、重复块、不可渲染 endpoint、inline comment 和最后一个可用 peer 均有拒绝或 raw-only 证据。
- location 支持 exact、prefix、`^~`、`~`、`~*`、named 六类 matcher，覆盖 nested 正反例、父规则变更后的子树合法性、重复、不可达、正则顺序和悬空引用诊断。
- static direct `proxy_pass` 可选择、替换或移除 upstream，并保留 port/URI；变量、重复 directive、动态目标和不能安全局部渲染的语法保持 raw-only。

## 工作区事务、API 与发布边界

批量草稿事务验证：

- `DraftSnapshot` 在共享锁内返回一次 canonical、digest 已验证的 draft 视图；读前后的 manifest 或内容不一致均拒绝。
- preview 绑定 canonical operation、当前强 ETag、before/after digest、完整 changed-file 集合和生成摘要；任一变化都使 preview 失效，客户端 patch 从不作为 apply 输入。
- `ReplaceFiles` 对路径稳定排序，拒绝重复路径、超限和非当前 ETag；逐文件同目录原子替换并记录实际有界 journal。
- crash matrix 证明部分文件写入会恢复完整 before，数据库已提交时只接受完整 after，第三种状态进入 `needs_attention`；不报告部分成功。
- 容量预检包含 before/after manifest、旧/新文件内容和实际 canonical journal 大小，而不是预留固定上限后漏算峰值。
- apply 前后只改变 workspace draft revision/digest；production digest 和 runtime 不由结构化服务修改。

API 契约同步到 `api/v1/openapi.yaml`，路径为：

```text
GET  /api/v1/config/workspaces/{workspace_id}/structured-config
POST /api/v1/config/workspaces/{workspace_id}/structured-config/previews
POST /api/v1/config/workspaces/{workspace_id}/structured-config/applications
```

HTTP 测试覆盖认证、Origin、CSRF、强 `If-Match`、strict tagged DTO、no-store、稳定领域错误、非 null 有界响应和脱敏 details。结构化 apply 只返回 draft workspace 结果；普通发布仍由既有 publish API 和 Agent 类型化事务执行。全仓 release/recovery 测试与真实 Nginx release 集成回归通过，证明结构化草稿没有旁路生产校验、备份、reload 或失败恢复。

  go test ./tests/integration -count=1 -v

  go test ./internal/runtime -count=1 -v

- `tests/integration` 的真实隔离 `nginx -t`、`nginx -T`、有效/无效 fixture、启动、回环请求、进程状态和清理通过。
- `internal/runtime` 的真实安全发布、reload、worker 替换、HTTP 终态确认、人工 restore 与固定 restart 回归通过。
- 测试使用独立 prefix、PID、日志、随机回环端口和临时目录；沙箱内受 macOS 进程限制的用例只在获准的沙箱外运行结果中计为通过。
