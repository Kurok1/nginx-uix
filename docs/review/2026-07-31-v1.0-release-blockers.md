## 1. 审计口径

本记录只把当前源码或当前环境中实际取得的证据标记为通过。v0.7.0 的历史 Docker、SBOM、漏洞扫描和 arm64 运行记录可以证明进入 v1.0.0 前的候选质量，但不能替代当前 `1.0.0` source fingerprint、本地 image ID、正式 manifest digest 和 runner 上的复验。

状态只使用：

- `PASS`：当前工作树已有可复现证据；
- `OPEN`：仓库内仍需实现、修复或执行；
- `EXTERNAL`：依赖用户决定、凭据、远端设置或外部 runner；
- `NOT RUN`：能力或脚本存在，但尚未在当前 1.0.0 候选上执行。

只要存在 `OPEN`、`EXTERNAL` 或阻断性的 `NOT RUN`，就不得创建正式 tag、GitHub Release 或发布镜像。

## 5. 建议关闭顺序

1. 已完成本地 1.0.0 元数据、脚本静态门禁和全仓 Go/前端质量复验。
2. 已将升级 fixture 从“仅 v0.6 长链”扩展为精确 v0.7.0→v1.0.0 直接升级，同时保留最旧 fixture 的长链兼容测试。
3. 已增加固定 10 轮 repeated-publish/recovery 和固定 600 秒/60 样本 stability harness，并在 arm64 exact image 上通过。
4. 已实现固定工具链远端 CI；经用户确认首次 push 后运行并回读真实 amd64 runtime、升级、恢复和完整 candidate matrix。
5. 用户已选择 Apache License 2.0，私密安全报告已启用并回读，`SECURITY.md` 已完成；首次 push 后继续验证默认分支/rules 与 GHCR 权限。
6. 构建唯一候选，完成双架构、SBOM、漏洞、稳定运行和最终验收记录。
7. 所有阻断项关闭后，再请求一次明确的 push/tag/image/Release 发布确认。
